# 脚本规范（团队约定）

> 定于 2026-11-04。适用 `scripts/` 下全部 Python 脚本，含以后新加的。
> 一句话：**打开文件第一屏就该看到全部可调参数；训练和批量脚本跑起来要有一条会动的进度条。**

| 配套文件 | 作用 |

| [`scripts/_ui.py`](../scripts/_ui.py) | 公共件：配置回显、进度条、日志。所有脚本共用，别各写一套 |
| [`scripts/templates/script_template.py`](../scripts/templates/script_template.py) | 可直接运行的新脚本模板，复制后改 CONFIG 和 `run_one()` |

为什么要定这条：改一个阈值要翻 200 行找 `0.25`；跑 282 张 val 或 736 帧视频时屏幕半天不动，分不清是卡住还是在算。两个毛病最后都会变成"只有一个人敢动脚本"。

## 一、文件骨架（固定六段，顺序不许乱）

```python
#!/usr/bin/env python
# -*- coding: utf-8 -*-
"""干什么 / 怎么跑（可复制命令）/ 输出什么 / 口径与验收值。"""   # ① 头注释

from __future__ import annotations
import argparse, sys
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent      # ② 路径与导入
sys.path.insert(0, str(ROOT / "scripts"))
from _ui import die, echo_config, progress, Tee

# ==================== 可调参数（只改这里） ====================   # ③ 配置区
MODEL = "yolo11s.pt"    # 预训练权重
EPOCHS = 50             # 轮数；960 基线就是 50
# ============================================================

def parse_args(argv=None): ...        # ④ 命令行：只做覆盖，默认值引用上面
def run_one(...): ...                 # ⑤ 业务
def main(argv=None) -> int: ...       # 主流程：读配置 → 回显 → 干活 → 汇总

if __name__ == "__main__":            # ⑥ 入口
    raise SystemExit(main())
```

要求：

- `main()` 只写流程，不写常量；
- 头注释必须能让人**不看代码就照抄命令跑起来**（写出完整命令、说明输出什么）。

## 二、可调参数怎么放（硬性 7 条）

1. **全部集中**在一个 `# ===== 可调参数 =====` 区，位置在 import 之后、任何函数之前，一般落在前 60 行。
2. **一行一个**，行尾注释写「单位 + 为什么是这个默认值」，例如 `WORKERS = 0  # Windows 下多进程容易卡死`。
3. **命名**：`全大写下划线`，单位进名字（`SLEEP_MS`、`MAX_FRAMES`、`IMGSZ`、`LIMIT`），布尔用 `IS_`/`ENABLE_` 开头。
4. **函数体里不许出现魔法数字**。只要有人可能想改，就提到上面；纯数学常数（如 `2.0` 取中点）可以留在原地。
5. **argparse 的 `default` 必须引用上面的常量**，不许把数值重写一遍，否则改一处忘一处：

   ```python
   p.add_argument("--epochs", type=int, default=EPOCHS)   # ✓
   p.add_argument("--epochs", type=int, default=50)       # ✗ 和 EPOCHS 必须手动同步
   ```

6. **路径必须从 `ROOT` 推导**，禁止写死盘符：`Path(r"F:\Competition\datasets")` 换台电脑就挂。
7. **开跑前把生效配置回显出来**（`echo_config`），`--dry-run` 只做到这一步。命令行覆盖后看到的必须是真正生效的值。

对照表：

| ✗ 不行 | ✓ 改法 |
|---|---|
| `0.25` 藏在第 180 行的 if 里 | 提成 `CONF_THRESHOLD = 0.25`，函数里用它 |
| `Path(r"F:\Competition\datasets\head_cls")` | `ROOT / "datasets" / "head_cls"` |
| `--limit` 默认值写在 argparse，顶部又写一遍 | 顶部定义，argparse 引用 |
| 只有 `--help` 能看出配置 | 每次运行都打印配置块 |

回显长这样（真实输出，`script_template.py --dry-run`）：

## 三、进度条（训练 / 批量脚本必须有）

### 3.1 三类脚本，三种做法

| 脚本类型 | 例子 | 进度条从哪来 |
|---|---|---|
| 调 `model.train()` | `train_detect.py` | **不用自己写**：ultralytics 自带 epoch + batch 两级 tqdm |
| 调 `model.val()` / 评测 | `eval_report.py` | ultralytics 自带 val 进度条 |
| 自己写循环（逐图 / 逐帧 / 逐条） | `video_regression.py`、挖负样本、裁片 | **必须自己加**，用 `_ui.progress()` |

### 3.2 样式对标 YOLO 训练

`ultralytics-8.3.163\Train.py` 本身**没有一行进度条代码**——那条 bar 是 `model.train()` 内部画的，格式定义在
`ultralytics\utils\__init__.py:44`：

```python
TQDM_BAR_FORMAT = "{l_bar}{bar:10}{r_bar}"
```

所以本项目的进度条统一用同一串格式（`scripts/_ui.py` 里的 `BAR_FORMAT`），和训练时看到的一模一样（下面为格式示意）：

```
处理: 100%|██████████| 282/282 [00:01<00:00, 210.4file/s, ms=56.1]
```

### 3.3 接入方式

**推荐**（自带降级与日志控制）：

```python
from _ui import progress

bar = progress(files, desc="推理", unit="file")
with bar:
    for p in bar:
        ...
        bar.set_postfix(hit=hit_count)
```

**手动步进**（总步数已知、循环写法不固定）：

```python
bar = progress(total=total_frames, desc="R1", unit="frame")
while True:
    ...
    bar.update(1)
    bar.set_postfix(ms=f"{ms:.1f}")
```

**不想要公共件**时的最小写法（必须带同样的 `bar_format`）：

```python
from tqdm import tqdm
for x in tqdm(items, desc="推理", unit="file", bar_format="{l_bar}{bar:10}{r_bar}"):
    ...
```

### 3.4 `progress()` 替你兜的三件事

- 没装 tqdm → 自动降级为**每 5% 一行**，脚本不会因为显示问题崩；
- `NO_PROGRESS=1` → 完全静默，批量写日志时用；
- 进度写 stderr，**不污染 stdout 的结果表和 JSON**（表还要拿去粘文档）。

### 3.5 训练脚本额外四条

1. **不要给 `.train()` 再套一层 tqdm**，两层够用，套三层会互相刷屏；
2. 训练进度条由 ultralytics 内部的 `TQDM` 画（`engine/trainer.py:386` 训练、`engine/validator.py:198` 验证），**不受 `verbose=False` 影响**；真要静音只能设环境变量 `YOLO_VERBOSE=False`，但那会把每轮指标一起吞掉，不要用；
3. 训练结束必须打印 `best.pt` 路径和 `results.csv` 路径，别让人去翻 run 目录；
4. Ctrl+C 中止后，立刻把那个 run 改名加 `_aborted`（AGENTS.md 第 8 条），不得当结果引用。

### 3.6 真实效果（`video_regression.py --max-frames 10`）

```
[视频] Pexels_11798561_workers_steel_frame_HD.mp4  736 帧  50 fps  1280x720
Pexels_11798561_worker:  30%|███       | 3/10 [00:19<02:13, 19.07s/frame, ms=6361.2]
Pexels_11798561_worker: 100%|██████████| 10/10 [00:19<00:00,  1.15s/frame, ms=1924.3]
```

> 这是试跑 10 帧的真实输出；首帧在初始化 CUDA（约 19 s），**不代表长视频耗时**。
> 736 帧的正式跑分仍以 `docs/实验规范.md` 里的 56.1 ms/帧 为准。

## 四、命令行契约

| 参数 | 谁必须有 | 说明 |
|---|---|---|
| `--dry-run` | 训练、以及会写文件的批量脚本 | 只回显配置，不占 GPU、不落盘 |
| `--quiet` | 输出较长的脚本 | 关掉进度条和表格，只留结果 |
| `--json X` / `--out X` | 出指标的脚本 | 落盘，便于跨次对比和贴进文档 |
| `--limit N` | 批量脚本 | 先跑 20 个试水，别一上来全量 |
| `--seed` | 训练、采样、增强 | 固定随机性，否则两次结果不可比 |

- 退出码：`0` 成功；`1` 可预期错误（文件缺失、环境不对）；`2` 用法错误（缺必填参数）；
- 缺必填参数时**不要只甩 argparse 的 usage**，给两行能直接复制的命令（见 [`train_detect.py`](../scripts/train_detect.py) 的写法）；
- **训练脚本连"用哪份数据、run 叫什么"也放进 CONFIG 区**（`DATA_YAML` / `RUN_NAME`），argparse 的默认值引用它们，命令行只做临时覆盖——这样改完文件直接跑就是对的，不用每次敲一长串；
- 可预期错误一律走 `_ui.die("中文说明")`，**只打中文、不打 traceback**；意外错误才让 traceback 出来；
- 需要 GPU 的脚本，在 `import ultralytics` 之前调 `_ui.require_torch("干什么")`，把"用错解释器"拦在加载模型之前；
- 带单位的参数名要有单位后缀：`--max-frames`、`--sleep-ms`、`--imgsz`。

## 五、日志与产物

- 长任务日志写 `.tmp/<名字>.log`，追加模式，用 `with Tee(path):` 包住主流程；
- **进度条不进日志**（走 stderr），日志里只留结果——进度条那种回车刷新会把日志搅烂；
- 目录归属：`runs/` 训练输出、`artifacts/` 共享产物、`.tmp/` 临时与日志；不要随手在根目录建文件夹；
- 脚本里不许编数据：没有结果就打印「待测试」，不填估算值（AGENTS.md 第 1 条）。

## 六、常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 用空 venv / 系统自带 python 跑脚本 | `ModuleNotFoundError: torch`，或报错指向 ultralytics 内部 | 已加 `require_torch()` 前置检查；训练/推理统一用装了 torch + ultralytics 的环境 |
| `--imgsz` 忘了传 | 跑出来的数和基线不可比 | 评测/分析脚本默认值已统一为 960；要跑 640 必须显式写 `--imgsz 640` |
| 控制台编不出 `█` | `UnicodeEncodeError` | `progress(..., ascii=True)` |
| 输出重定向到文件后 bar 变成一行行 | 正常现象（非 tty） | 写日志时直接 `NO_PROGRESS=1` |
| 换掉 `sys.stdout` 后打印顺序乱 | 输出缓冲 | 关键 `print` 加 `flush=True` |
| `workers > 0` 时 bar 刷新卡顿 | 多进程 + stderr 争用 | 训练保持 `workers 0`；进度条只放在主进程外层 |
| 中文宽度对不齐 | 配置块歪掉 | `echo_config` 已按显示宽度补空格，自己写就用它 |

## 九、遗留问题（不在脚本里，改不动但要知道）

- `ultralytics-8.3.163/.../cfg/datasets/SHWD.yaml` 里的 `path:` 仍是绝对路径 `F:\...`。脚本已经全部用 `ROOT` 推导 yaml 位置，但**换电脑或挪仓库时，这个 yaml 内部还得改一行**。`datasets/shwd_neg/SHWD_neg.yaml` 同理（`path: F:/Competition/datasets/shwd_neg`）。
- 处理办法：挪仓库时两个 yaml 各改一行 `path:`；或者在 `datasets/` 下放一个用相对路径的新 yaml，`--data` 指过去。

## 十、怎么开始写新脚本

```powershell
# 1) 复制模板
Copy-Item scripts\templates\script_template.py scripts\你的脚本名.py

# 2) 改三处：头注释、可调参数区、run_one()
# 3) 先 dry-run 看配置
python scripts\你的脚本名.py --dry-run
```
