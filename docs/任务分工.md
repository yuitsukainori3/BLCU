# 任务分工（两周冲刺）

> 日期：2026-11-01
> 现状：两类模型（head / helmet）已有三版结果，最新 v3 = SHWD 2,274 张训练、自有 45 张 val，`head` AP 0.669 / `helmet` 0.942；应用层还没开始。
> 假设：4—5 人小组。3 人或 6 人以上的调整见第 4 节。

## 0. 先定三条规矩

1. **按交付物分工，不按"技术模块"分工**。每个人手里都要有一个能给别人看的东西（数据集、脚本、页面、文档），不是"我负责学习"。
2. **每条任务写清"完成"的定义**。没有验收标准的任务，最后都会变成"差不多了"。
3. **每周一次 20 分钟同步**：每人说三句——做完了什么、卡在哪、下周做什么。卡住超过一天必须喊人，不许自己耗。

## 1. 角色

| 角色 | 负责什么 | 需要的能力 |
|---|---|---|
| **数据** | 标注、质检、数据版本 | 细心、能看懂标签规则；不需要写代码 |
| **实验** | 训练、评测、消融表 | 会跑命令、会看指标；能改脚本更好 |
| **系统** | 两路推理、跟踪投票、事件存储 | Python，会接 API |
| **应用** | Web 界面、演示 | 前端基础（Flask/FastAPI + 简单页面即可） |
| **文档** | 文档、PPT、视频脚本 | 写作、排版 |

一个人可以兼两个角色，但**数据**和**实验**最好分开——自己标自己测，出了问题发现不了。

## 2. 任务清单

### 数据（关键路径，最先启动）

| 编号 | 任务 | 工时 | 完成标准 |
|---|---|---:|---|
| D1 | 从源数据再抽 100 张自有图，人工标 head/helmet，并入 val | 3 人日 | val 从 45 → 145 张，裸头 ≥40 框；按 v1.2 规则；抽 10% 交叉复核 |
| D2 | 现有 150 张标签质检 | 0.5 人日 | 抽查 30 张，记录错标/漏标数；白帽标成裸头的一律改 |
| D3 | 数据版本记录 | 0.5 人日 | `datasets/README` 里写清每次训练用的是哪份数据、多少张 |

### 实验（和训练机绑定）

| 编号 | 任务 | 工时 | 完成标准 |
|---|---|---:|---|
| E1 | 固定训练配置与命名规范 | 0.5 人日 | `Train.py` 参数写死；run 名字带 `数据_imgsz_轮数` |
| E2 | 三组训练：v3 训满 120 轮、merged、merged_r5 | 1 人日（机器跑） | 三份 `results.csv` + 三张 PR 曲线 |
| E3 | `scripts/eval_report.py` | 1 人日 | 一条命令输出：逐类 AP、混淆矩阵、**误合规率**、分尺度召回 |
| E4 | 消融表维护 | 每次 10 分钟 | 一行一个实验：配置 / head / helmet / 误合规率 / 备注 |

**误合规率定义**（团队统一口径）：`真值是 head、被预测成 helmet 的框数 ÷ 真值 head 总框数`。当前 v3 是 3/10 = 30%。

### 系统（不依赖模型训好，现在就能写）

| 编号 | 任务 | 工时 | 完成标准 |
|---|---|---:|---|
| S1 | 两路推理 pipeline | 2 人日 | 输入一帧，输出 person 框 + 头框 + 归属结果；用现成 `best.pt` 就能跑 |
| S2 | 跟踪 + 连续帧投票 | 2 人日 | 同一 track 连续 15 帧里 ≥60% 违规才告警；有冷却 |
| S3 | 事件存储 + 抓拍裁剪 | 1 人日 | 每条事件存：时间、track_id、抓拍图（裁整个人，不是一颗头）、状态 |

### 应用（最小可用即可）

| 编号 | 任务 | 工时 | 完成标准 |
|---|---|---:|---|
| A1 | Web 界面 | 2 人日 | 上传图片/视频 → 显示框和状态 → 事件列表（含截图） |
| A2 | 实时视频流 | 2 人日 | 接一路 RTSP 或本地摄像头，掉帧不影响判定 |

### 文档

| 编号 | 任务 | 工时 | 完成标准 |
|---|---|---:|---|
| W1 | 项目文档最终稿骨架 | 1 人日 | 表 9 改成两类；5.4 节改成"两路检测"；指标位置留空待填 |
| W2 | 消融表汇总成一页 | 0.5 人日 | 5—8 行，每行能追溯到 run 目录 |
| W3 | 演示视频脚本 + 素材清单 | 1 人日 | 分镜 + 每段要拍的画面；不写解说词先 |

## 3. 两周排期

| | 第 1 周 | 第 2 周 |
|---|---|---|
| 数据 | D1 启动（每天 3 小时） | D1 收尾、D2、D3 |
| 实验 | E1、E3，E2 挂机跑 | E2 三组对比、E4 |
| 系统 | S1 | S2、S3 |
| 应用 | A1 骨架 | A1 收尾 |
| 文档 | W1 | W2、W3 |

**关键路径**：D1（标注）→ 最终指标 → W1 填数。标注不完成，所有"提升"都没法写进材料。

## 4. 按人数调整

| 人数 | 怎么分 |
|---|---|
| 3 人 | 甲：数据 + 文档；乙：实验 + 系统；丙：应用 + 演示。**砍掉 A2 和 S3** |
| 4 人 | 数据 / 实验 / 系统 / 文档+应用。**砍掉 A2** |
| 5 人 | 按第 1 节五个角色，各一人；系统一人做不完时文档的人顶上 S3 |
| 6 人以上 | 系统拆成"推理"和"业务规则"两人；数据拆成"标注"和"质检"两人 |

## 5. 风险

| 风险 | 表现 | 应对 |
|---|---|---|
| 标注拖期 | D1 一周做不完 100 张 | 降到 60 张，或两人轮换标 + 第三人复核 |
| 训练机排队 | 三个人同时要跑实验 | 排班表；小实验用 640、50 轮（30 分钟） |
| 系统等人 | S1 等模型定稿 | 不等：现在就用 `train4/best.pt` 写，模型换了只改权重路径 |
| 文档最后赶 | 第 2 周末才动笔 | W1 第 1 周必须出骨架，指标留空也能先写 |

## 6. 怎么判断"这周没白干"

周末对照这张表：

- 数据：val 多了几张？质检发现几个错标？
- 实验：多了几行消融表？误合规率有没有降？
- 系统：pipeline 能不能对一张图输出"人 + 头 + 合规/违规/不确定"？
- 应用：能不能点一个按钮看到结果？
- 文档：最终稿的章节标题是不是都齐了？

任何一项答"没有"，下周第一件事就是把它补上。
