# 手部误检核查（视频实测）

> 日期：2026-11-04
> 素材：`datasets/Pexels_11798561_workers_steel_frame_HD.mp4`（**未标注原片**，1280×720、50 fps、736 帧、14.7 秒）
> 模型：`artifacts/weights/helmet_v0.1.0.pt`（960 输入）
> 参数：与展示系统一致——`imgsz 960`、原始 `conf 0.05`、head 生效阈值 **0.18**、逐帧推理
> 裁图：[手部误检_裁图.jpg](手部误检_裁图.jpg)

## 结论

**确认存在"手/手套被识别为 head"的持续误检**，而且不是偶发。

| 项目 | 数值 |
|---|---:|
| `head` 检出（conf ≥0.18） | **308 次 / 736 帧** |
| 聚成簇数 | 10 |
| 前 3 簇合计 | **276 次**（占 90%） |
| 簇位置 | x 600—720、y 360—400（工人手部） |
| 框宽中位 | **18—19 px** |
| 置信度范围 | **0.18—0.59** |
| 出现时间跨度 | **3.2 s — 14.6 s**（大半个视频） |

前 3 簇明细：

| 簇中心 | 帧次 | 时间跨度 | 置信度 | 宽中位 |
|---|---:|---|---:|---:|
| (720, 400) | 159 | 3.8—14.6 s | 0.18—0.40 | 19 px |
| (600, 400) | 70 | 4.2—14.2 s | 0.18—**0.59** | 18 px |
| (680, 400) | 47 | 3.2—12.1 s | 0.18—0.46 | 18 px |

## 为什么这个误检特别难处理

| 常规手段 | 为什么失效 |
|---|---|
| **提高阈值** | 置信度最高到 **0.59**，阈值提到 0.6 会把真头一起删掉 |
| **时序投票** | 它**持续几十帧**（3.2—14.6 s），投票反而会把它确认为"稳定事件" |
| **裁片复核/拒识** | 裁片只有 18 px，放大到 224 是一团糊，分类器同样分不清 |
| **"头在人框上部"的位置规则** | 工人弯腰作业时，手正好落在人框上部——规则失效 |

**第 4 条尤其关键**：展示系统里已有 `assign_head_to_person(head_region_ratio=0.35)`，但这个场景下"弯腰的人"会让手部进入头部区域。

## 建议的修法：难例回灌（背景样本）

把这段视频里被误检的手部区域裁出来，**作为"无目标"背景样本**（空标签）加进训练集：

1. 从 3 个簇里各取 10—20 个不同姿态的裁片，扩到 640×640（或直接按原尺寸贴到空白画布）；
2. 放进 `datasets/shwd/images/train/` 并配**空标签文件**（Ultralytics 支持背景图，用来压低 FP）；
3. 与现有 2,274 张一起重训 50 轮；
4. 对比：val 的 FP（当前 79）与这段视频的手部误检次数（当前 276）。

**预期**：手部误检明显下降，val 误合规基本不变（它不是分类问题，是"这不是目标"的问题）。

**风险**：背景样本过多会压低召回，建议先加 30—60 张，小步验证。

## 这段素材的价值

它同时提供了两样东西：

1. **一个可复现的失败案例**（不是猜的，有帧号、坐标、置信度）；
2. **一个可验证的改进实验**（加负样本前后，同一段视频的手部误检次数）。

写进文档就是完整的"发现 → 归因 → 干预 → 验证"链路。
