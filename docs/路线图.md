# 技术路线（当前版）

> 日期：2026-11-03
> 依据：960 实验的分层与错误分解结果 + 两阶段讨论 + 老师 11-02 的复评意见。
> 所有数字标「实测」的可追溯；标「目标」的是验收线，不是现状。

## 0. 一屏现状（实测）

| 项目 | 数值 |
|---|---|
| 数据 | SHWD：train 2,274 / val 282 / test 662 |
| 检测 960 | mAP50 0.8561、head AP50 0.7428 |
| 违规召回 | 68.2%（103/151） |
| 误合规 | 7.3%（11/151） |
| 误报（背景框） | 65 个 / 282 图 |
| 单张推理 | 18.2 ms（RTX 5060） |

**错误结构（head，151 个框）：**

| 类型 | 640 | 960 |
|---|---:|---:|
| 判对 | 89 | 104 |
| 误合规 | 11 | 11 |
| 低置信 | 18 | 8 |
| 定位偏差 | 5 | 3 |
| 完全没检出 | 28 | 25 |

## 1. 三个判断（路线由它们决定）

**判断一：分辨率这条路已经吃到头了。**
640→960 用 3 倍训练时间换来 +9.3 个召回点；再往上（1280）成本继续翻倍，而剩下的漏检（25 个）中位只有 23×26 px，多数属于"极小目标"，边际收益递减。

**判断二：剩下的 11 个误合规，是独立问题。**
分辨率完全没动它们（11→11），说明不是"像素不够"，而是判别能力问题。→ 这是两阶段的靶子，也是创新点的立论。

**判断三：误报（65 个）不该用模型解。**
分类器没有"拒识"能力，硬用它过滤会误杀真头（双阈值方案已论证走不通）。真正吃 FP 的是**时序投票**——单帧误报不会连续 15 帧出现在同一位置。

## 2. 路线总览（四阶段，带门）

```text
P0 两阶段验证 ──┐
   （2-3 天）    │ 门 G1 通过？
                 ├─ 是 → P1 视频闭环 → P2 界面与材料 → P3 可选增强
                 └─ 否 → 转“不确定态”方案，两阶段降级为记录
```

| 阶段 | 核心任务 | 工期 | 出口标准（门） |
|---|---|---|---|
| **P0** | 分类器训满 + 路由接入 + 三组阈值 | 2—3 天 | G1：误合规 ≤5%，召回 ≥66.2% |
| **P1** | 自采视频 + 跟踪投票 + 事件 | 2 天 | G2：事件级误报 ≤ 帧级 1/5 |
| **P2** | 最小界面 + 消融汇总 + 材料 | 2 天 | G3：能演示"上传→结果→事件列表" |
| **P3** | other 类 / 切片推理 / 1280（按需） | 各 1—2 天 | 由 P1 的遗留问题决定 |

## 3. 逐阶段说明

### P0：两阶段验证（当前阶段）

**做什么**

1. 分类器训满 30 轮（`python ml/train_cls.py --epochs 30 --name cls_v1`）；
2. 写 `ml/two_stage.py`：检测 → 尺寸路由 → 裁片分类 → 覆盖；
3. 跑 3 组 margin 阈值（0.1 / 0.2 / 0.3），每组出分层表；
4. 记录：分类器改判了多少个、改对几个、改错几个。

**门 G1（三条同时满足）**

- 总误合规：7.3% → **≤5%**；
- `>60px` 档误合规：9.8% → **≤6.5%**；
- 违规召回：68.2% → **≥66.2%**（允许掉 2 个点）。

**不过门怎么办**：不硬推。把结论写进文档（"两阶段在本数据上收益不足"），转 P0-B 备选——不确定态（margin 小就标"不确定"，不告警），半天工作量，同样能降误合规。

### P1：视频闭环（老师硬要求）

**做什么**

1. 自采 3 段 × 30 秒：白天正常作业、远景小目标、人群密集（有条件加夜间）；
2. ByteTrack 跟踪（`model.track(persist=True)`）；
3. 滑窗投票：15 帧内违规比例 ≥0.6 才告警，冷却 30 秒；
4. 输出事件：时间、track_id、抓拍图（裁整个人不是一颗头）、状态。

**门 G2**

- 事件级误报数 ≤ 帧级误报数的 **1/5**；
- 每段视频能产出完整事件列表，无程序崩溃。

**为什么它排第二**：FP 的 65 个主要靠这一层吃掉；同时它是老师明确要求的"完整测试"。

### P2：界面与材料

- 最小界面：上传 → 显示框与状态 → 事件列表（含截图）；
- 消融表汇总（640 / 960 / 两阶段 / 阈值组）；
- 按评分项整理材料（创/技/量/健/美），素材见 [复评技术说明](复评技术说明.md)。

**门 G3**：能在 3 分钟内完整演示一遍，无手动操作代码。

### P3：可选增强（按 P1 结果决定）

| 触发条件 | 做哪个 | 成本 |
|---|---|---|
| 事件级误报仍 >5 次/小时 | other 类（拒识） | 1.5 天 |
| 远景小目标仍是主要漏检 | 切片推理（SAHI） | 1 天 |
| 部署端算力宽裕、追求召回 | 1280 输入 | 90 分钟/轮 |
| 要求"单模型部署" | 补 person 标注做联合对照 | 3 小时标注 + 1 天 |

**不满足触发条件就不做**——这是防止功能堆砌的闸门。

## 4. 并行线（不占主线时间）

| 事项 | 谁 | 何时 |
|---|---|---|
| seed 1/2 复现 960，给"±范围" | 实验组 | 挂机，与 P0 并行 |
| 数据质检：<10px 的框（train 100 个 / val 7 个）统一口径 | 数据组 | P0 期间 |
| 文档初稿（创/技两节） | 文档组 | P0—P1 期间 |

## 5. 明确不做

| 不做 | 理由 |
|---|---|
| 换模型（YOLOv12 / RT-DETR） | 边际收益低，且解释成本高 |
| 加注意力模块 | 无法证明有效，老师明确反对堆叠 |
| 双阈值过滤 FP | 分类器 conf 不具备"是不是目标"的语义（已论证） |
| 全量两阶段（所有框都复核） | 小框裁片不可靠，且延迟翻倍 |
| 实时视频流、多人报表 | 功能堆砌，老师要求砍 |

## 6. 时间轴（含门）

```text
第 1 周  ├─ P0 分类器训练 ──┐
        ├─ P0 路由接入 ────┤→ G1
        └─ 并行：seed、数据质检
第 2 周  ├─ P1 拍视频 ──────┐
        ├─ P1 跟踪投票 ────┤→ G2
        └─ P2 界面骨架
第 3 周  ├─ P2 材料汇总 ────┤→ G3
        └─ P3（按需）
```

## 7. 一句话

> **先用两阶段证明"判错"能修；再用视频证明"误报"能压；最后才谈扩展。**
> 每一阶段都有门，过不了就换备选，不硬推。
