# 两路检测方案（人体 + 头部）

> 版本：v0.1（2026-11-01）
> 状态：设计稿。文中标“实测”的数字都来自本机（RTX 5060 Laptop 8G）对 `small_dataset` 45 张 val 的真实测量；
> 标“待实测”的是等两类模型训好后需要补的。
> 关联：[标签规则](标签规则.md) v1.2（两类）、[实验记录](实验记录.md)。

## 0. 一句话

**通用人体模型负责“人在哪、跟住谁”，专用头部模型负责“这颗头戴没戴”，两者在业务层用几何关系合并。**
`person` 不作为训练类别，只作为运行时的辅助输出。

## 1. 为什么拆成两路

同一批 45 张 val、147 个人工标注的 person 框，IoU 0.5 匹配，输入 960：

| 方案 | conf 0.25 | conf 0.40 | conf 0.50 |
|---|---|---|---|
| COCO 预训练 `yolo11s.pt`（不训练） | **R 0.905** / P 0.756 | **R 0.871** / P 0.853 | **R 0.837** / P 0.891 |
| 自训三分类模型里的 person 类 | R 0.776 / P 0.809 | R 0.748 / P 0.833 | R 0.721 / P 0.891 |

（COCO 一行是本方案实际要用的配置；自训一行取自 `runs/detect/train2/weights/best.pt`，该模型有 3 类，person 是其中一类。）

两个结论：

1. **现成的 COCO 权重比自训的 person 好 8—13 个召回点**，而且不用标一张图。
2. person 的精确率在低阈值下偏低，部分原因是团队原来的 person 标注本身有漏标——这不影响它做“跟踪锚点”，但说明它不能当评测的真值。

## 2. 结构

```text
视频帧 / 图片
   │
   ├─ A 路：yolo11s.pt（COCO，classes=[0]）
   │        └→ person 框 + ByteTrack 的 track_id
   │
   └─ B 路：best.pt（head / helmet 两类，自训）
            └→ 头部框（每颗头一个）
                     │
                     ▼
              归属：头框落在哪个 person 的“头部区域”
                     │
                     ▼
              单帧状态 → 按 track_id 连续帧投票 → 告警 / 抓拍 / 入库
```

两路模型**分开训练、分开评估**，唯一耦合点是第 5 节的归属规则（纯几何，不需要训练）。

## 3. A 路：人体检测 + 跟踪

| 项 | 取值 |
|---|---|
| 权重 | `yolo11s.pt`（Ultralytics 官方 COCO 权重，本地已缓存） |
| 类别 | `classes=[0]`（只取 person） |
| 输入 | 960（与 B 路一致，便于共享预处理分辨率） |
| 置信度 | **0.40** 起步（R 0.871 / P 0.853）；人少场景可降到 0.25 换召回 |
| 跟踪 | `model.track(..., persist=True)`，ByteTrack |
| 职责 | ① 提供 track_id 作为投票的载体 ② 抓拍时裁整人 ③ 人数统计 |

它**不参与**“戴没戴”的判定——判定只由 B 路输出决定。

## 4. B 路：头部检测

| 项 | 取值 |
|---|---|
| 权重 | 自训两类模型（`head=0` / `helmet=1`） |
| 输入 | 960 |
| 置信度 | 0.25 起步；`head` 与 `helmet` 可分开设（待实测） |
| 输出 | 每颗头**只出一个框**（两类互斥） |

“一颗头一个框”是这个方案的关键性质：**框的数量就是头的数量，框的类别就是判定结果**，不需要再做“头盔是否落在头上”的二次判断。

## 5. 归属：头框 → 人

规则（按顺序）：

1. 取 person 框的上部 35% 作为“头部区域”；
2. 头框中心落在某个人的头部区域内 → 归属该人（多人重叠时取中心距离最近的）；
3. 不落在任何人的头部区域内 → 记为**独立头**：正常判定、正常抓拍，但没有 track_id，不参与连续帧投票。

```python
def head_region(box, ratio=0.35):
    x1, y1, x2, y2 = box
    return x1, y1, x2, y1 + (y2 - y1) * ratio

def assign(head_box, persons):
    cx, cy = (head_box[0] + head_box[2]) / 2, (head_box[1] + head_box[3]) / 2
    best_id, best_d = None, float("inf")
    for pid, pbox in persons:
        x1, y1, x2, y2 = head_region(pbox)
        if x1 <= cx <= x2 and y1 <= cy <= y2:
            d = abs(cx - (pbox[0] + pbox[2]) / 2)
            if d < best_d:
                best_id, best_d = pid, d
    return best_id          # None = 独立头
```

## 6. 单帧状态与连续帧投票

单帧三态：

| B 路输出 | 单帧状态 |
|---|---|
| `helmet` | 合规 |
| `head` | 违规候选 |
| 没有框 | 未知（不告警） |

按 track_id 累计，避免“一帧抖动就报警”：

| 参数 | 初始值 | 说明 |
|---|---:|---|
| 滑窗长度 | 15 帧 | 约 0.6 s @25fps |
| 违规比例阈值 | 0.6 | 窗口内 ≥60% 帧是“违规候选”才告警 |
| 最短有效帧数 | 10 | 轨迹太短不判定 |
| 告警冷却 | 30 s | 同一 track_id 冷却期内不重复告警 |

以上是**初始值，需在真实视频上标定**（见第 11 节）。

## 7. 代码骨架

```python
from collections import defaultdict, deque
from ultralytics import YOLO

HEAD, HELMET = 0, 1
person_model = YOLO("yolo11s.pt")
head_model = YOLO("runs/detect/train3/weights/best.pt")   # 两类模型训好后的路径

votes = defaultdict(lambda: deque(maxlen=15))
last_alarm = {}

def process(frame, ts):
    pr = person_model.track(frame, persist=True, imgsz=960, conf=0.40,
                            classes=[0], verbose=False)[0]
    persons = []
    if pr.boxes.id is not None:
        persons = list(zip(pr.boxes.id.cpu().numpy().astype(int),
                           pr.boxes.xyxy.cpu().numpy()))

    hr = head_model.predict(frame, imgsz=960, conf=0.25, verbose=False)[0]
    for box, cls in zip(hr.boxes.xyxy.cpu().numpy(),
                        hr.boxes.cls.cpu().numpy().astype(int)):
        pid = assign(box, persons)
        if pid is None:
            report_standalone(box, cls)      # 独立头：只记录
            continue
        votes[pid].append("violate" if cls == HEAD else "ok")

    for pid, q in votes.items():
        if len(q) < 10 or sum(v == "violate" for v in q) / len(q) < 0.6:
            continue
        if ts - last_alarm.get(pid, -1e9) < 30:
            continue
        last_alarm[pid] = ts
        fire_alarm(pid, crop_person(pid))    # 抓拍裁整人，不是裁一颗头
```

## 8. 实测性能

45 张图逐张推理（batch=1、`device=0`、含 letterbox 与 NMS）：

| 模型 | imgsz | 推理 | 含前后处理 | 两路合计 | 等效帧率 |
|---|---:|---:|---:|---:|---:|
| COCO `yolo11s` | 640 | 10.4 ms | 22.6 ms | 32.0 ms | ≈31 fps |
| 自训头部模型 | 640 | 5.3 ms | 9.4 ms | | |
| COCO `yolo11s` | 960 | 21.2 ms | 29.8 ms | 59.8 ms | ≈17 fps |
| 自训头部模型 | 960 | 18.2 ms | 30.0 ms | | |

- 960 + 两路在 5060 上约 17 fps，处理 25 fps 视频会掉帧；**建议采集端抽帧到 12—15 fps**，或降到 640 跑（31 fps）。
- COCO 模型在 640 下前后处理明显更重（80 类的 NMS），真实视频里预处理可以复用，实际差距会小一些。
- 上边缘设备时两路都换 `yolo11n`，帧率能再翻一倍左右（待实测）。

## 9. 失败模式与对策

| 现象 | 原因 | 对策 |
|---|---|---|
| 远处的人没有 person 框 | COCO 小目标弱 | 不影响判定：头框仍会出，只是变成“独立头”；跟踪类功能在该区域降级 |
| 头框归属错人 | 人群密集、person 框重叠 | 取中心最近；仍歧义的帧不计入投票（宁可漏，不可错） |
| 裸头被判成 helmet | 两类混淆（当前约 4/10） | B 路给 `head` 单独调低阈值；业务层“拿不准”时输出“不确定”而不是“合规” |
| 两路框对不上（人动了、头没跟） | 两路独立推理、时间戳不一致 | 同一帧内两路推理，不做异步；帧号对齐后再归属 |
| 视频 25 fps 跑不满 | 两路 960 约 60 ms | 抽帧、降分辨率、或换 n 模型 |

## 10. 和“单模型三类”的对比

| 维度 | 两路（本方案） | 单模型三类 |
|---|---|---|
| person 数据 | 不需要标 | 需要标 + 复核（当前 386/147 框，质量一般） |
| person 召回（实测） | 0.871 @conf 0.4 | 0.748 @conf 0.4 |
| 延迟 | 约 2 倍 | 1 倍 |
| 部署 | 两个模型文件 | 一个模型文件 |
| 训练相互影响 | 无（各训各的） | person 的标注噪声会拉低 head/helmet |
| 答辩叙事 | “通用人体 + 专用头部，两级检测” | “一个模型三分类” |

结论：**精度和标注成本上两路更优，延迟和部署上单模型更优**。当前阶段选两路。
