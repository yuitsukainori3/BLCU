# 名词解析

> 日期：2026-11-01
> 用途：给组员对口径、写文档时查词。每条都带本项目的真实数字，别只背定义。
> 遇到不懂的词，先在这里搜；搜不到再问。

## 一分钟版（最常被问的五个）

| 词 | 一句话 |
|---|---|
| **召回** | 该找到的，找到了多少 |
| **精确率** | 找到的里面，有多少是对的 |
| **违规召回** | 裸头（违规）里，被正确找到的比例。本项目 = 89/151 = **58.9%** |
| **误合规率** | 裸头里，被判成“戴了安全帽”的比例。本项目 = 11/151 = **7.3%** |
| **mAP** | 综合精确率和召回、并且对所有置信度阈值积分后的一个总分 |

---

## 一、指标类

### 准确率 / 精确率（Precision）

**定义**：模型报出来的框里，有多少是真的。

**公式**：`P = 判对的框数 ÷ 报出来的框总数`

**例子**：val 里模型报了 113 个 head 框，其中 89 个对，14 个框在空地上，10 个其实是头盔 →
`P = 89 / 113 = 78.8%`

**别搞混**：精确率高说明“报得准”，但可能漏掉很多——只报最有把握的那一个，精确率能到 100%。

### 召回率（Recall）

**定义**：标注里有的目标，模型找到了多少。

**公式**：`R = 判对的框数 ÷ 标注框总数`

**例子**：val 里有 151 个裸头，模型判对 89 个 → `R = 89 / 151 = 58.9%`

**别搞混**：召回率高说明“漏得少”，但可能报一堆错的。

### 违规召回（本项目的自定义指标）

**定义**：真值 `head`（裸头，也就是违规）里，被**正确判成 head** 的比例。

**公式**：`违规召回 = 判成 head 且真的对 ÷ 真值 head 总数`

**例子**：89 / 151 = **58.9%**

**注意两件事**：
1. 它是**工作点上**的数字（conf=0.25、IoU=0.45），换个阈值数就变；
2. 它和“head AP50 = 0.68”不矛盾——AP 是对所有阈值积分的总分，召回是某一个工作点的切片。

**为什么单列这个指标**：安全帽系统最怕漏报违规。用 mAP 看不出“到底漏了多少人”，用召回能。

### 误合规率（本项目的自定义指标）

**定义**：真值 `head` 里，被**判成 helmet** 的比例。方向最恶劣的错误——没戴判成戴了。

**公式**：`误合规率 = 判成 helmet 的裸头数 ÷ 真值 head 总数`

**例子**：11 / 151 = **7.3%**

**别搞混**：它和“漏检”不是一回事。漏检是“没看见”，误合规是“看见了但判错”。

### TP / FP / FN / TN

| 词 | 含义 | 在本项目里 |
|---|---|---|
| TP | 判对了 | 裸头判成 head |
| FP | 多报了 | 空地上报了个 head；头盔报成 head |
| FN | 漏掉了 | 裸头没检出来；裸头判成 helmet |
| TN | 正确没报 | 背景确实没有目标 |

**记忆**：P 看 FP（多报），R 看 FN（漏报）。想提召回就是压 FN，想提精确率就是压 FP。

### IoU（交并比）

**定义**：两个框的重叠程度，交集面积 ÷ 并集面积，0—1。

**用途**：
- 判断“这个预测算不算对”：IoU ≥ 0.5 才算命中；
- 判断“框画得准不准”：AP50-95 就是用 0.5—0.95 十个阈值平均。

**例子**：GT 框和一个预测框重叠 60% → IoU≈0.6，在 0.5 阈值下算对，在 0.75 阈值下算错。

### AP / AP50 / AP50-95 / mAP

- **AP**：把置信度从高到低扫一遍，画出“精确率—召回率”曲线，曲线下的面积就是 AP。它同时奖励“准”和“全”。
- **AP50**：只要求 IoU ≥ 0.5 时的 AP。
- **AP50-95**：IoU 从 0.5 到 0.95 每 0.05 算一次 AP，取平均。**反映框画得准不准**。
- **mAP**：所有类别 AP 的平均。两类就是 `(AP_head + AP_helmet) / 2`。

**本项目基线**：val mAP50 = 0.8207、mAP50-95 = 0.6304、head AP50 = 0.6818。

**别搞混**：mAP50 高但 mAP50-95 低，说明“找得到但框不准”。

### 混淆矩阵（Confusion Matrix）

**定义**：一张表，行是“模型预测的类”，列是“真实的类”，格子里是框数。

**本项目 val（conf 0.25、IoU 0.45）**：

| 预测 \ 真值 | head | helmet | 背景 |
|---|---:|---:|---:|
| head | 89 | 10 | 14 |
| helmet | 11 | 692 | 58 |
| 背景（没报） | 51 | 45 | — |

**怎么读**：看对角线（89、692）是判对的；看“head 行、helmet 列”的 10 表示“把头盔误报成裸头”；看“helmet 行、head 列”的 11 就是**误合规**。

### 置信度阈值（conf）

**定义**：模型给每个框一个 0—1 的分数，低于阈值就丢掉。

**影响**：阈值调低 → 召回升、精确率降；调高 → 反之。

**注意**：**所有召回/精确率数字都必须带阈值**，否则没有意义。本项目混淆矩阵固定用 0.25。

### 漏检 vs 误检

- **漏检（FN）**：该有的没报。本项目 51 个裸头完全没检出。
- **误检（FP）**：不该报的报了。本项目 14 个 head 框落在空地上。

## 二、数据类

### 训练集 / 验证集 / 测试集

| 集合 | 用来干嘛 | 本项目 |
|---|---|---|
| train | 训练 | SHWD 2,274 张 |
| val | 调参、选模型、做消融 | SHWD 282 张 |
| test | 最后跑一次，报最终成绩 | SHWD 662 张 |

**铁律**：test 一旦用来调参，就不再是 test 了。

### 标注框与归一化坐标

**定义**：YOLO 的标签一行一个目标：`类别 x中心 y中心 宽 高`，四个数都是 0—1，除以图片宽高。

**例子**：`0 0.512 0.433 0.120 0.180` = 一个 head，中心在图的 51%/43% 处，宽高占 12%/18%。

### 类别不平衡

**定义**：不同类别的样本量差很多。

**本项目**：head 966 个框 vs helmet 6,421 个框，约 1:6.6。模型天然偏向多数类，裸头更容易被漏或判错。

### 难例（Hard Example）

**定义**：模型反复出错的样本。本项目的 51 个漏检裸头就是难例。

### 伪标签（Pseudo-Labeling）

**定义**：用模型给未标注的图打标，再当训练数据。

**风险**：模型的错会被学走，越滚越大。**伪标签绝不能进 val/test**。

### 数据增强（Augmentation）

**定义**：训练时对图片做随机变换，变相扩数据。

**常见**：mosaic（四图拼接）、mixup（两图混合）、copy-paste（把目标贴到别的图）、scale（缩放）、hsv（色调/亮度）。

### 过拟合 / 欠拟合

- **过拟合**：训练集越来越好，val 反而变差。信号是 val loss 回升、mAP 掉。
- **欠拟合**：训练集和 val 都上不去。信号是 loss 居高不下、mAP 低。

**本项目**：v1 在 105 张图上训 120 轮，第 42 轮后就开始过拟合。

### 域偏移（Domain Shift）

**定义**：训练数据的样子和实际使用的样子不一样。

**本项目**：SHWD 的图短边 469 px，你们自己的图只有 333 px。同一个模型在两边 mAP50-95 差 0.24。

## 三、训练类

### epoch / batch / 学习率

- **epoch**：把所有训练图过一遍。本项目 50 轮。
- **batch**：一次送进显存的图数。`batch=-1` 让框架自动选。
- **学习率**：每步更新的幅度。太大震荡，太小学不动。YOLO 默认带 warmup + 衰减。

### 预训练 / 微调 / 冻结

- **预训练**：先在别的数据上训好（如 COCO 的 `yolo11s.pt`）。
- **微调**：在预训练权重上继续训自己的数据。
- **冻结**：训的时候不让某些层更新（`freeze=10` 冻结前 10 层），小数据时防过拟合。

### best.pt / last.pt

- **last.pt**：最后一轮的权重。
- **best.pt**：按 fitness 选出的最好一轮。fitness = `0.1 × mAP50 + 0.9 × mAP50-95`，偏重框的精度。

### seed 与随机性

**定义**：固定随机种子能让训练可复现。

**为什么强调**：即使固定 seed，不同硬件/库版本仍会有 0.01—0.02 的抖动。所以对比实验要跑 3 个 seed 取均值。

## 四、系统类

### 跟踪 track_id

**定义**：给视频里同一个目标分配一个稳定编号，跨帧不变。

**用途**：判断“是不是同一个人”，才能做连续帧投票、统计人数、抓拍。

### 帧级 vs 事件级

- **帧级**：一帧算一次。视频 25 fps，抖一下就报警。
- **事件级**：同一个人连续违规才记一次事件，有开始/结束时间。

**产品看事件级，不是帧级。**

### 滑窗投票

**定义**：看最近 N 帧里违规占多少比例，超过阈值才告警。

**本项目建议**：窗口 15 帧、比例 ≥0.6、冷却 30 秒。

### 两路检测

**定义**：一个模型找人（COCO person），一个模型找头并判戴没戴。

**为什么**：person 是通用任务，现成权重就够；头部判定是专用任务，要自己训。

### 不确定态

**定义**：模型没把握时输出“不确定”，进人工复核，而不是硬判合规/违规。

**触发方式**：`|p_helmet - p_head| < 0.2`。

## 五、方法论类

### 基线（Baseline）

**定义**：所有对比的起点。没有基线，任何“提升”都没有意义。

**本项目基线**：train4（SHWD train、640、50 轮），mAP50 0.8207。

### 消融实验（Ablation）

**定义**：一次只改一个变量，看它单独贡献多少。

**反例**：同时开 960 + P2 + 新增强，涨了也不知道是谁的功劳。

### 错误分解

**定义**：把错误按原因分类，而不是只看总数。

**本项目**：151 个裸头 → 89 对、11 判成头盔、51 没检出。三类错误对应三种不同策略。

### 置信度校准

**定义**：让模型输出的分数接近“真实正确的概率”。

**为什么要**：模型说 0.9 的框，实际可能只有 0.7 是对的。不校准，阈值就没有可解释性。

---

## 附：三个最容易搞混的地方

1. **召回 58.9% 和 head AP50 0.68**：前者是某个阈值下的切片，后者是全部阈值的积分。不是矛盾，是两把尺子。
2. **误合规 ≠ 漏检**：漏检是没看见，误合规是看见了判错。前者靠分辨率/数据，后者靠分类边界。
3. **mAP 高 ≠ 好用**：mAP 是类别平均、阈值无关的；产品关心的是“某个告警量下漏了多少违规”。所以要单列违规召回。
