# 学习路线（v3：SHWD 单数据集 + 策略方向）

> 日期：2026-11-01
> 前提：数据固定为 SHWD 自己的划分（train 2,274 / val 282 / test 662），两类 `head` / `helmet`；
> 评测口径固定为 [`scripts/eval_report.py`](../scripts/eval_report.py)，结果记在 [评测记录](评测记录.md)。
> 基线（train4，640 输入，50 轮）：val mAP50 **0.8207**、mAP50-95 0.6304、head AP50 **0.6818**、
> helmet AP50 0.9596、**违规召回 58.9%（89/151）**、**误合规率 7.3%（11/151）**。

## 0. 先把靶子换掉

上一版路线的假设是“数据太少、测不出来”，现在两条都不成立了：训练集 2,274 张，val 里有 151 个裸头框，5 个点的变化能稳定看见。

所以现在的瓶颈非常明确：

| 指标 | 现在 | 目标 | 为什么是它 |
|---|---:|---:|---|
| **违规召回**（裸头被找到的比例） | **58.9%** | ≥75% | 41% 的违规头根本没被检出，这是产品最直接的漏报 |
| 误合规率（裸头被判成戴帽） | 7.3% | ≤5% | 判错方向最致命，但量已经不大 |
| 事件级误报 | 未测 | 待测 | 需要视频，第 3 周才有 |

**主线只有一条：把违规召回从 59% 拉到 75%。** 其余都是配角。

## 1. 四周路线

每周都有仓库产出，产出物直接进 Git，不要只“看完视频”。

### 第 0 周（2 天）：建立实验纪律

**目标**：会用评测脚本，会从混淆矩阵里读出“下一步该改什么”。

- 跑一遍 `eval_report.py`，对照 `docs/评测记录.md` 看懂每个数字的来源；
- 理解为什么用 `val` 调参、`test` 只跑一次；
- 学会写“假设—实验—结论”三行：假设什么、改了什么、结果如何。

**产出**：`docs/评测记录.md` 本周新增 3 条实验行，每条都带一句假设。

### 第 1 周：检测原理 + 把召回打上去

**目标**：知道召回低是“没检到”还是“检到了但归类错”，并能用 4 种手段分别验证。

先做一次**误差分解**（全周最重要的一件事）。基线 val 的 151 个裸头里：

```
89 个判对（58.9%） / 11 个判成 helmet（7.3%） / 51 个完全没检出（33.8%）
```

“没检出”是大头，所以本周的主攻方向是检测能力，不是分类。

| 手段 | 做法 | 成本 | 预期 |
|---|---|---|---|
| 训练更久 | 50 → 120 轮 | 1 小时 | 最便宜的验证 |
| 提高分辨率 | 640 → 960 | 3 倍时间 | 小目标直接受益 |
| P2 检测头 | 复制模型 yaml 加一层 | +30% 时间 | 专门给小目标 |
| 阈值扫描 | 推理端调 conf，不重训 | 10 分钟 | 看召回-精确率曲线 |

**学习内容**：YOLO 的 Backbone / Neck / Head、P3/P4/P5 各管多大目标、正负样本分配、CIoU 与 DFL 损失。

**产出**：`docs/评测记录.md` 里 4 组消融（基线 / 长训 / 960 / P2），每组重点看“违规召回”。

### 第 2 周：两级判定（策略核心）

**目标**：把“找头”和“判戴没戴”拆开，用分类器补检测器的召回。

思路：检测器输出所有头框（head + helmet 都算候选）→ 每个框裁出来外扩 1.3 倍 → 小分类器判 helmet / bare head。

**为什么这条最有希望**：分类器的训练样本是**每一个头框**——SHWD 能切出 6,421 个 helmet 片 + 966 个 head 片，是图片数量的 3 倍多；而且分类器看的是高分辨率头部特写，不受整图缩放影响。

**学习内容**：迁移学习（用 `yolo11n-cls.pt` 微调）、类别不平衡、阈值选择、置信度校准。

**产出**：`ml/head_classifier.py` + 对比表（检测直接判 vs 检测+复核，看违规召回和误合规率）。

### 第 3 周：跟踪与时序（需要视频）

**目标**：把“帧级抖动”变成“事件级稳定”。

- ByteTrack 的核心思想：按置信度分两段关联，低分框也能救回来；
- 滑窗投票：同一 track 连续 15 帧里 ≥60% 判违规才告警；
- 事件级指标：不是“错了多少帧”，而是“误报了几次、漏报了几次”。

**前提**：需要一段 50 帧以上的工地视频。没有就先去拍，别拿公开视频凑。

**产出**：`ml/pipeline.py` + 事件级误报/漏报表。

### 第 4 周：收尾

- 把四周的消融汇总成一页表；
- 挑 20 张典型失败案例（远景、遮挡、逆光、误判 helmet）出图；
- 每个结论配一句“代价是什么”（时间、误报、部署复杂度）。

### 三条实验规矩

1. **一次只改一个变量**。同时开 960 + P2 + 新增强，涨了也不知道是谁的功劳。
2. **跑 3 个 seed**（`seed=0/1/2`）。2,274 张图的训练本身仍有 0.01—0.02 的抖动，单次结果不下结论。
3. **test 只在最后跑一次**。拿 test 调参，最终数字就不可信了。

## 3. 不要做

| 想法 | 为什么劝退 |
|---|---|
| 自己设计新主干/新损失 | 2,274 张图撑不起，也没有对比价值 |
| 加注意力模块追涨点 | 评审见得多，收益通常 <2 个点，还要跑 3 个 seed |
| 换 YOLOv12 / RT-DETR | 先把召回做到 75%，换模型是最后一步 |
| 用 test 调参 | 一旦用了，test 就废了，最终数字不再可信 |
| 只跑一次不记结果 | `--append` 一行的事，别靠脑子记 |

## 4. 检查点

- 第 0 周：能说清 `mAP50` 和“违规召回”分别回答什么问题；
- 第 1 周：能解释“为什么 960 比 640 好”，并用你们自己的数说明；能独立跑完一组消融；
- 第 2 周：能说清“分类器补召回”的原理，并给出误合规率的前后对比；
- 第 3 周：能区分钟级指标和事件级指标，并说明为什么后者更接近产品。
