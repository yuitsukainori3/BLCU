# 模型差异化：学习路线与资料

> 日期：2026-11-01（v2，按“训练集会并入 SHWD”更新）
> 对象：大二团队，能投入约 6—10 小时/周，目标是在现有 YOLO11s 两类模型上做出**能讲清楚、能验证**的差异化。
> 前提：自有 150 张 + SHWD 全部 3,218 张（`datasets/shwd`，含它的 val/test）都进训练，训练集 3,323 张；`head` AP 0.47、`helmet` 0.92；已有两路检测方案（COCO person + 自训头部）。

## 0. 先说清楚：差异化到底从哪来

评审看的不是“你加了什么模块”，而是**问题—方法—证据**能不能闭环。

**训练量已经不是瓶颈**：SHWD 的 3,218 张全部并入后，训练集 3,323 张，够训到收敛，也够做结构消融了。所以“105 张图做不出消融”这个理由不再成立。

**但评测的尺子还是 45 张、10 个裸头框**——这才是现在的真实限制。训练集变大**不会**让 val 变可信：head 错一个框 AP 就跳 0.1。而且在“SHWD 全量进训练”之后，**连辅助 val 都没有了**，所有结论只能靠这 45 张。所以在讨论“加什么结构”之前，先解决“怎么量”。

**真正能拉开差距的是这四件事**（按性价比排序）：

| 方向 | 具体做法 | 为什么算差异化 | 难度 |
|---|---|---|---|
| ① 系统策略 | 两路检测 + 头人归属 + 跟踪投票 + “不确定”态 | 大多数队伍只做单帧检测，你们有完整状态机 | 中 |
| ② 小目标专治 | `imgsz 960` + P2 检测头 + SAHI 切片推理，做对比表 | 有明确数据支撑（裸头中位 41×65 px） | 低 |
| ③ 数据效率 | SHWD 预训练 → 自有数据微调；伪标签；主动学习挑帧 | “105 张自有数据 + 公开数据”的组合本身有故事 | 中 |
| ④ 评测严谨性 | 分场景/分尺度/分遮挡的 AP 表 + 失败案例 | 评审最容易信服，也最难造假 | 低 |

结构层面现在可以动的：**P2 小目标检测头**（改一行 yaml）、**更高输入分辨率**、**更强的数据增强**。加注意力模块也“能测”了，但优先级排在后面（见第 3 节）。

### 0.1 训练量上去之后，什么变了、什么没变

| | 变了 | 没变 |
|---|---|---|
| 训练 | 105 张 → 3,323 张，能训到收敛 | — |
| 结构实验 | 加模块、换 P2、改损失，能测出信号了 | 仍要跑 **3 个 seed** 再下结论，单次结果不可信 |
| 评测 | — | 唯一 val 是自有 45 张（10 个裸头框），噪声 ±0.1；SHWD 的 val 也进训练了，没有辅助 val |
| 域 | 模型见到更多工地/图库场景 | SHWD 上的表现以后**无法单独评估**，只能看自有 val |

## 1. 学习路线（4 周，可压缩到 2 周）

每周都有**产出物**，产出物直接进仓库，不要只“看完视频”。

### 第 0 周（2 天）：先把“评测”搞明白

**目标**：能解释清楚 mAP50 / mAP50-95 / P / R / conf 阈值之间的关系，知道你们的 0.469 是怎么算出来的。

- 读：Ultralytics 的 [Val 模式文档](https://docs.ultralytics.com/modes/val/) + COCO 评测指标说明
- 做：写一个 `scripts/eval_report.py`，对 `best.pt` 输出：
  - 逐类 AP50 / AP50-95
  - 按框面积分档（小/中/大）的召回
  - 分场景（逆光/遮挡/远景）的人工标注小表
- 产出：一张“基线评测表”，后面所有改动都跟它比。

### 第 1 周：目标检测基础 + YOLO 结构

**目标**：能在白板上画出 YOLO11 的结构，说清每个 loss 在干什么。

必须搞懂的 6 个概念：
1. bbox 回归与 IoU、NMS（含 soft-NMS）
2. anchor-based vs anchor-free（YOLO11 是 anchor-free）
3. FPN / PAN 的多尺度融合（P3/P4/P5 分别对应多大目标）
4. 正负样本分配（YOLO11 用 TOOD 风格的 task-aligned assigner）
5. 损失：分类 BCE、框回归 CIoU、DFL（Distribution Focal Loss）
6. mAP 的计算流程（PR 曲线 → 插值 → 平均）

- 读：《动手学深度学习》第 13 章（计算机视觉）—— [中文版免费](https://zh.d2l.ai/)
- 看：李沐 B 站“论文精读”里的 YOLO 系列（搜“李沐 YOLO”）
- 看：[Ultralytics 文档](https://docs.ultralytics.com/) 的 Models / Train 两节
- 做：用 `model.model` 打印 YOLO11s 的层结构，对照 yaml 逐层写注释
- 产出：`docs/YOLO11结构笔记.md`（含结构图 + 每个 loss 的作用）

### 第 2 周：小目标 + 数据效率（本项目的核心）

**目标**：能说清“为什么裸头难”，并掌握 4 种应对手段。

- 小目标为什么难：下采样后特征消失、正样本太少、标注尺度不一致
- 手段 1：**提高输入分辨率**（你们已做 640→960，+0.074）
- 手段 2：**P2 检测头**（stride=4，给小目标单独一层）
- 手段 3：**SAHI 切片推理**（大图切块分别检测，[GitHub obss/sahi](https://github.com/obss/sahi)）
- 手段 4：**数据增强**：mosaic、copy-paste（把小目标贴到大图上，直接增加正样本）
- 数据效率：伪标签（teacher-student）、主动学习（挑模型最不确定的帧标）

- 读：SAHI 的论文与 README（“Slicing Aided Hyper Inference and Fine-tuning for Small Object Detection”）
- 读：Soft Teacher（半监督检测，arXiv 搜标题）——只看思想，不必复现
- 做：在 `smalldata.yaml` 基础上加一个 P2 版本的模型 yaml，训一次，和基线对比
- 产出：消融表第一版（基线 / +960 / +P2 / +SAHI）

### 第 3 周：跟踪、融合与部署

**目标**：把“两路 + 跟踪 + 投票”跑通，并测出延迟。

- 跟踪：ByteTrack 的思想（按置信度分两段关联，低分框也能救回来）
- 融合：头框归属 person 的几何规则（已在 [两路检测方案](两路检测方案.md) 里）
- 部署：`model.export(format="onnx")`，用 onnxruntime 测延迟；了解 INT8 量化
- 做：把 `process(frame)` 跑在 50 帧视频上，统计误报/漏报
- 产出：`ml/pipeline.py` + 一张“精度—速度”对比表

### 第 4 周：收尾

- 把 4 周的消融表汇总成一页
- 挑 20 张典型失败案例（逆光、重叠、远景、误判 helmet）做图
- 写清楚：每个改动带来多少提升，代价是什么

### 实验设计三条规矩（训练量上来后必须守）

1. **一次只改一个变量**。同时开 960 + P2 + 新增强，涨了也不知道是谁的功劳。
2. **跑 3 个 seed**（`seed=0/1/2`）。3,300 张图的训练本身仍有 0.01—0.02 的抖动，head 在 45 张 val 上更是 ±0.1；不跑 seed 的对比没有意义。
3. **只有一把尺子，就用交叉验证补**：SHWD 全量进训练后，能评测的只剩自有 150 张。
   单次 45 张 val 的噪声太大，做对比实验时用 5 折交叉验证（`build_merged.py --folds 5 --fold k`，
   每折 30 张 val），报 5 折的均值和标准差；只跑单折的结论不要写进文档。

### 论文（只精读 3 篇，其余看摘要）

1. **Focal Loss / RetinaNet**（arXiv 搜 “Focal Loss for Dense Object Detection”）——理解正负样本不平衡
2. **ByteTrack**（arXiv 搜 “ByteTrack”）——你们要用的跟踪
3. **SAHI**（arXiv 搜 “Slicing Aided Hyper Inference”）——小目标切片

其余按需查：YOLOX（anchor-free 与解耦头）、TOOD（任务对齐分配）、Copy-Paste（小目标增强）、Soft Teacher（半监督）。

## 3. 不建议走的路

| 想法 | 为什么劝退 |
|---|---|
| 加 CBAM/SE/注意力模块 | 现在能测了，但性价比低：评审见得多，且 SHWD 的域和你们现场不同，涨点不一定迁移 |
| 自己设计新主干/新损失 | 时间不够，且没有大规模数据验证 |
| 换 YOLOv12/RT-DETR 等新模型 | 先把数据做厚，换模型是最后一步 |
| 一上来读综述 | 综述是给写论文的人看的，不是给做项目的人看的 |
| 只看视频不动手 | 每个知识点必须在仓库里有对应产出 |

## 4. 检查点：怎么知道自己学会了

- 能不看资料画出 YOLO11 的结构，并说出 P3/P4/P5 各负责多大的目标；
- 能解释“为什么 960 比 640 好”，并用你们自己的数据说明；
- 能独立跑出一张消融表，且每个数字都能复现；
- 能在 3 分钟内给非技术的人讲清楚“两路检测”为什么比单模型好。

## 5. 和项目进度的关系

- 第 0—1 周：不耽误训练，边学边补数据；
- 第 2 周：训练量已经够，P2 和 SAHI 可以直接做；但每次只改一个变量、跑 3 个 seed；
- 第 3 周：依赖两类模型训好（当前还没跑）；
- 第 4 周：留出至少 3 天写文档，不要卡在截止前一天。

> 另外一个前提：自有 val 只有 45 张。如果能再补 100 张自有图做 val（只标 head/helmet，不训练），
> 上面所有结论的可靠性会明显提升——这件事的优先级高于任何结构改动。
