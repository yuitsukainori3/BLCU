# 安全帽智检 · 初期方案

**基于 YOLO11 的工地安全帽佩戴检测与 Web 管理终端**

## 一、选题

我们要做的是：**用工地现有的摄像头，自动发现没有戴安全帽的人，并把结果做成一个给工地管理层用的网页终端。**

选这个题，是因为安全帽检查目前基本靠人工巡查、班前检查和抽查：作业面分散、人员流动，很难持续盯住；夜间、远处、逆光时人眼也看不清；真出了违规，往往只有口头提醒，缺少能回看的记录。工地上摄像头本来就有，缺的是"看得过来"的那一层。

我们不打算提出新的网络结构，也不追求在公开榜单上刷指标。重点是把成熟的检测模型用到工地场景里，把误报压住，把系统做成能演示、能交付的东西——这也是我们作为本科生团队比较现实的目标。

## 二、目标

分三层：

1. **检测**：用 YOLO11 训练一个安全帽佩戴检测模型，区分"戴了安全帽"和"没戴（裸头）"。
2. **匹配**：用 COCO 预训练的模型检测出画面里的人，再把每个头部框按位置归到具体某个人身上，回答"是谁没戴"，而不只是"画面里有人没戴"。
3. **呈现**：做成一个网页管理终端，接摄像头看实时画面，出告警、留记录、能统计。

前两层是模型和判定逻辑，第三层是产品形态。

## 三、准备怎么做

**1）数据**
以公开安全帽数据集为主（例如 SHWD），先跑通训练流程；再用团队自采或公开视频补充工地场景，按场景划分训练集和验证集，避免同一段视频的相邻帧同时进两边。

**2）模型**
用 YOLO11 的 s 规模做迁移学习，只设"戴 / 不戴"两类，一颗头只出一个框——框的数量就是头的数量，框的类别就是结论，业务层不用再做二次判断。先跑基线，再根据误报和漏检补数据、调整输入尺寸。

**3）人—头盔匹配**
两路推理：一路用 COCO 预训练权重只取人（不重新训练），一路用自训的头盔模型。把人的框上部当作头部区域，头框中心落在谁的区域里就归谁；归不上的头单独记录，不参与后续投票。这样既能说清"谁没戴"，也能在抓拍时裁出整个人，而不是一颗头。

**4）判定与去抖**
单帧结果只作为候选：同一个人在连续多帧里都被判为"没戴"才告警，同一个人短时间内不重复报。参数先给经验值，之后用现场视频标定。

**5）系统**
后端负责拉流、推理、判定和存事件；前端是网页，负责画面、告警、事件和统计。先做单机版，跑在局域网里的一台机器上，不依赖云。

## 四、最终成品大概什么样

一个**网页**，管理层用浏览器打开、登录就能用，不用装客户端：

- **实时监控**：多路摄像头画面，画面里画出检测框；有违规时，对应画面和右侧告警卡片同时提示。
- **告警**：每条告警带抓拍截图、时间、摄像头，可以点"已处理"或"误报"。
- **事件中心**：按时间、摄像头、状态查历史记录，点开看大图。
- **统计**：按天、按摄像头看违规趋势，可导出表格。
- **设置**：增删摄像头、调阈值、切换模型版本。

演示时用笔记本接一个 USB 摄像头或放一段录像就能跑，不强依赖工地现场，这样答辩时比较稳。

## 五、范围与边界

- 只做安全帽佩戴这一件事；不做人脸识别、身份与考勤，不做反光背心等其他劳保用品，也不做跨摄像头追踪。
- 定位是"辅助提醒"，不替代现场安全管理；夜间、强逆光、远距离和严重遮挡不承诺稳定识别。
- 拍摄现场画面前要取得管理方许可，对外材料里的人脸打码，现场视频不外传。

## 六、大致阶段

1. 数据与基线模型：把两类模型训出来，能在一批图上给出可信的结果；
2. 判定逻辑：两路推理 + 归属 + 多帧投票，先在离线视频上跑通；
3. Web 终端：摄像头接入、告警、事件、统计；
4. 联调与演示：用模拟或现场视频回归，准备答辩演示。

## 七、想请老师把关的几点

1. 这个切入点（工程应用为主、不追求算法创新）在比赛里是否站得住？
2. "COCO 出人 + 自训模型出头"的两路方案，和"一个模型同时检测人、戴帽、裸头"相比，老师更倾向哪种？我们目前倾向前者，理由是人的标注成本高、现成模型更稳。
3. 现场摄像头数据不好拿。如果最终只能用公开数据和自采视频，作品的说服力够不够？
4. 以我们的时间和人手，功能范围要不要再收缩？
