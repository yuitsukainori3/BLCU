# 策略学习路线：有哪些、有什么用、怎么用

> 日期：2026-11-01
> 对象：安全帽检测项目（SHWD 划分，2 类，val 151 个裸头框）
> 当前基线：违规召回 **58.9%**（89/151）、误合规 **7.3%**（11/151）、mAP50 0.8207
> 主线目标：违规召回 ≥75%，误合规 ≤5%
> 说明：这里说的“策略”都是**不改网络结构**的做法——数据怎么用、模型怎么训、结果怎么判、系统怎么串。

## 0. 地图：策略分五层

| 层 | 解决什么 | 代表策略 |
|---|---|---|
| **A 数据层** | 模型没见过 / 见得太少 | 标签清洗、难例挖掘、重采样、增强、伪标签、主动学习 |
| **B 训练层** | 模型学得不够好 | 预训练+微调、多尺度、高分辨率、蒸馏、集成、学习率调度 |
| **C 推理层** | 一次前向的结果不够准 | 分类型阈值、TTA、切片推理、级联复核、不确定态 |
| **D 时序层** | 单帧结果抖 | 跟踪、滑窗投票、事件聚合、跨帧补漏 |
| **E 系统层** | 模型和业务接不上 | 两路检测、分级告警、人机协同、错误分解、阈值选点 |

一句话记法：**A 决定上限，B 决定能不能摸到上限，C/D 决定实际用起来好不好，E 决定能不能讲清楚。**

## 1. 先按问题选策略

| 你遇到的现象 | 先试 | 再试 | 基本没用 |
|---|---|---|---|
| 违规召回低（漏检裸头） | 误差分解 → 高分辨率 / 长训 | 小目标贴图、切片推理、降 head 阈值 | 换主干 |
| 误合规高（裸头判成戴帽） | 级联复核分类器 | 不确定态、分类型阈值 | 加注意力 |
| 画面抖、反复告警 | 跟踪 + 滑窗投票 | 事件级冷却 | 调 conf |
| 换场景就崩 | 伪标签、主动学习、预训练+微调 | 域随机化（降质增强） | 堆数据量 |
| 部署跑不动 | 蒸馏、量化、换 n 模型 | 切片推理只在必要时开 | 上大模型 |

## 2. 策略卡片

每张卡片的格式：**是什么 → 解决什么 → 怎么用 → 成本 / 怎么验证**。

### A 数据层

**A1 标签清洗（Label Cleaning）**
- 是什么：找出标注错误并修正，而不是加新数据。
- 解决什么：SHWD 已知有错标（戴白帽的头被标成裸头）、漏标（背景里的人没框）。错标会直接压低可达上限。
- 怎么用：用当前 `best.pt` 在 val 上跑推理，导出两类样本——①置信度 >0.6 但无对应 GT 的框（疑似漏标）；②GT 是 head 但模型稳定判 helmet 的（疑似错标）。每类抽 30 张人眼看，改完的图另存一个修正版标签目录。
- 成本：1 人日。**验证**：修完后同一模型重测，误合规率应下降。

**A2 难例挖掘（Hard Example Mining）**
- 是什么：把漏检/误检的样本单独拎出来，分析共性。
- 解决什么：盲目加数据效率低，先搞清楚“难在哪”。
- 怎么用：取基线漏检的 51 个裸头，统计它们的框面积、与最近的 helmet 框的 IoU、所在图像亮度。如果 70% 都是小框 → 走分辨率；如果多与 helmet 重叠 → 走分类边界。
- 成本：半天。**验证**：产出一张“漏检画像”表，直接决定后面投哪。

**A3 重采样（Re-sampling / 过采样）**
- 是什么：让稀有类在训练中更常出现。
- 解决什么：head 966 个框 vs helmet 6,421 个框（1:6.6），模型天然偏向 helmet。
- 怎么用：三种做法，从轻到重——①复制含 head 框的图片 2—3 次（改 train.txt 即可，`build_merged.py` 已有类似逻辑）；②自定义 Dataset 的采样器，按类别频率开方加权；③离线把 head 小图贴到无头背景上（等于合成，见 A5）。
- 成本：1 小时。**验证**：违规召回是否上升，同时看 helmet AP 有没有掉。

**A4 数据增强（Augmentation）**
- 是什么：在不加数据的前提下扩大分布。
- 解决什么：过拟合、尺度/光照不鲁棒。
- 怎么用：Ultralytics 内置参数就够——`scale=0.5`（尺度抖动）、`mosaic=1.0`、`mixup`（慎用，检测任务易糊）、`hsv_v`（亮度）、`close_mosaic=10`。想模拟低画质再自己加一步离线降采样 + JPEG 压缩。
- 成本：改参数，几小时。**验证**：固定其它变量，只开/关一项，看 val。

**A5 小目标合成（Copy-Paste）**
- 是什么：把 head 小图贴到大图空地上，制造更多小目标样本。
- 解决什么：小目标正样本太少，模型学不会。
- 怎么用：从原图裁出 head 区域（带少量背景），随机缩放后贴到其它图的天空/墙面区域，同步生成标签。Ultralytics 的 `copy_paste` 只对分割标签生效，检测任务要自己做。
- 成本：1—2 天。**验证**：只在小框（<32²）上比较召回。

**A6 伪标签（Pseudo-Labeling）**
- 是什么：用模型给未标注图打标，筛选后当训练数据。
- 解决什么：没有标注预算，但能拿到大量现场图/视频帧。
- 怎么用：`predict(save_txt=True, save_conf=True)` → 只保留 conf>0.7 且面积合理的框 → 人工抽查 5% → 混入训练集，比例不超过 1:3。
- 成本：半天起步。**风险**：错误会滚雪球，**绝不能用伪标签做 val**。

**A7 主动学习（Active Learning）**
- 是什么：只标模型最不确定的样本。
- 解决什么：标注预算有限时，把人力花在刀刃上。
- 怎么用：对未标注帧计算“最大类别概率”或“head/helmet 分数差”，挑最低的 100 帧人工标。每轮重训后再挑。
- 成本：需视频素材。**验证**：同样标注量下，主动学习 vs 随机抽样的召回对比。

### B 训练层

**B1 预训练 + 微调（两阶段）**
- 是什么：先在大数据上训，再在小数据上精调。
- 解决什么：小数据直接训容易过拟合、收敛慢。
- 怎么用：`YOLO("runs/detect/train4/weights/best.pt").train(data=自有或现场数据, epochs=30, lr0=1e-3)`。冻结骨干可选：`freeze=10`。
- 成本：30 分钟。**验证**：微调前后在**同一 val** 上对比——注意别用训练过的数据当 val。

**B2 高分辨率训练**
- 解决什么：小目标在高分辨率下才有足够像素。
- 怎么用：`imgsz=960`（或 1280）。显存不够就降 batch。
- 成本：3 倍时间。**验证**：看小框（<32²）的召回分档变化。

**B3 多尺度训练**
- 是什么：每个 batch 随机换输入尺寸。
- 解决什么：对尺度变化更鲁棒。
- 怎么用：`multi_scale=True`（Ultralytics 支持，配合 `imgsz` 为 32 的倍数）。
- 成本：几乎为零。**验证**：固定 val，看 head 在小/中/大三档的召回是否更均衡。

**B4 蒸馏（Knowledge Distillation）**
- 是什么：大模型当老师，把知识压到小模型。
- 解决什么：部署端算力不够，但又不想掉精度。
- 怎么用：老师 `yolo11x` 在你的数据上训到最好，学生 `yolo11n` 用它的软标签/特征蒸馏。Ultralytics 不内置检测蒸馏，需要自己写 loss。
- 成本：3—5 天。**建议**：等项目后期、部署有明确算力约束时再做。

**B5 模型集成（Ensemble / WBF）**
- 是什么：多个模型的框融合。
- 解决什么：单模型有随机性，融合能稳定涨 1—2 个点。
- 怎么用：训 3 个不同 seed 的模型，推理时用 WBF（加权框融合）合并，再 NMS。
- 成本：推理翻 3 倍。**验证**：集成 vs 单模型的 mAP 与延迟。

### C 推理层

**C1 分类型阈值**
- 是什么：不同类别用不同的 conf。
- 解决什么：head 漏检多、helmet 误报多，用一个阈值必然顾此失彼。
- 怎么用：推理后按类别过滤：`head` 用 0.15（保召回），`helmet` 用 0.35（保精确）。Ultralytics 的 `classes` 参数只能选类，不能分别设阈值，需要在结果后处理里做。
- 成本：1 小时。**验证**：画“召回—精确率”曲线，选业务点。

**C2 TTA（测试时增强）**
- 是什么：推理时做翻转/多尺度，结果融合。
- 解决什么：小样本模型不稳，TTA 能免费涨一点点。
- 怎么用：`model.val(augment=True)` 或 `predict(augment=True)`。
- 成本：2—3 倍推理时间。**验证**：mAP 涨多少、延迟涨多少，值不值。

**C3 切片推理（SAHI）**
- 是什么：大图切块分别检测再合并。
- 解决什么：远景小目标在原图里只有几十像素。
- 怎么用：`sahi` 库，或自己切 2×2 重叠切片，推理后用 NMS 合并。
- 成本：4 倍推理。**验证**：只在大图（>2000px）上开。

**C4 级联复核（两级判定）**
- 是什么：检测器出候选，再用分类器判类别。
- 解决什么：检测器要同时管定位和分类，小目标上顾不过来。
- 怎么用：①用 GT 框把训练集的头全裁出来（外扩 1.3 倍），按 head/helmet 建分类数据集；②训 `yolo11n-cls`；③推理时对每个检测框裁片再分类，用分类结果覆盖检测类别。
- 成本：2—3 天。**验证**：违规召回、误合规率的前后对比。

**C5 不确定态（Reject Option）**
- 是什么：模型没把握时输出“不确定”，而不是硬判。
- 解决什么：误合规的代价远大于“多一次人工看”。
- 怎么用：`p_helmet` 与 `p_head` 的差值 < margin（如 0.2）→ 标为不确定，进复核队列。
- 成本：半天。**验证**：画“误合规率 vs 复核量”曲线。

### D 时序层

**D1 目标跟踪（ByteTrack）**
- 是什么：给每帧的框分配稳定 ID。
- 解决什么：单帧抖动、重复告警、无法统计“同一个人”。
- 怎么用：`model.track(source, persist=True, tracker="bytetrack.yaml")`。
- 成本：1 天。**验证**：ID 切换次数、轨迹完整度。

**D2 滑窗投票**
- 是什么：连续 N 帧里超过比例才告警。
- 解决什么：偶发误判引发告警。
- 怎么用：每个 track 维护长度 15 的队列，违规比例 ≥0.6 才触发；配合 30 秒冷却。
- 成本：半天。**验证**：事件级误报数。

**D3 事件级聚合**
- 是什么：把“帧”聚合成“事件”。
- 解决什么：评审/用户关心的是“报了几次警”，不是“错了多少帧”。
- 怎么用：同一 track 连续违规 → 一个事件；事件有开始/结束时间、抓拍图、置信度。
- 成本：1 天。**验证**：每小时事件数、人工复核通过率。

### E 系统层

**E1 两路检测（person + head）**
- 是什么：通用人体模型 + 专用头部模型。
- 解决什么：头框太小不好跟踪；需要“人在哪”做归属和抓拍。
- 怎么用：见 [两路检测方案](两路检测方案.md)。
- 成本：2 天。**验证**：归属正确率、抓拍可用率。

**E2 分级告警**
- 是什么：按置信度分“确定违规 / 疑似违规 / 不确定”。
- 解决什么：一刀切阈值要么太吵要么太漏。
- 怎么用：高置信直接告警，中置信进复核列表，低置信只记录。
- 成本：半天。**验证**：不同等级的人工通过率。

**E3 错误分解（Error Decomposition）**
- 是什么：把 FN 按原因分类，而不是只看总数。
- 解决什么：不知道该往哪投人力。
- 怎么用：对每个漏检的 GT 框，记录它的大小档、是否被遮挡、最近的 helmet 框 IoU、图像亮度。做一张分布表。
- 成本：半天。**验证**：这张表直接决定下一周做什么。

**E4 阈值选点**
- 是什么：用业务指标而不是 mAP 选 conf。
- 解决什么：mAP 最优点不等于业务最优点。
- 怎么用：扫 0.1—0.6，画“违规召回 / 误合规 / 每小时告警数”三条曲线，选一个可接受的平衡点。
- 成本：1 小时。**验证**：业务方（或你们自己扮演）能否接受这个告警量。

## 3. 学习顺序（按策略族，4 周）

| 周 | 学哪一族 | 具体策略 | 产出 |
|---|---|---|---|
| 0 | E（评测） | E3 错误分解、E4 阈值选点 | 漏检画像表 + 阈值曲线 |
| 1 | A + B（数据与训练） | A2 难例、A3 重采样、A4 增强、B2 高分辨率、B3 多尺度 | 4 组召回消融 |
| 2 | C（推理） | C1 分类型阈值、C4 级联复核、C5 不确定态 | 复核分类器 + 对比表 |
| 3 | D（时序） | D1 跟踪、D2 投票、D3 事件聚合 | pipeline + 事件级指标 |

E1（两路检测）放第 3 周之后，属于系统集成，不占学习主线。

## 5. 针对你们现在这套系统的组合

按当前数字（召回 58.9%、误合规 7.3%），性价比排序：

1. **E3 错误分解**（半天）→ 决定后面投哪，不做就是瞎猜；
2. **B2 高分辨率 + A4 增强**（半天）→ 最便宜的召回提升；
3. **C1 分类型阈值**（1 小时）→ 不动模型就能提召回；
4. **A3 重采样**（1 小时）→ 缓解 1:6.6 的类别失衡；
5. **C4 级联复核**（2—3 天）→ 策略层的主菜；
6. **C5 不确定态**（半天）→ 配合 C4 收尾；
7. **D1—D3**（1 周）→ 有视频之后再做。

## 6. 不建议用的策略

| 策略 | 为什么现在别碰 |
|---|---|
| 检测知识蒸馏 | 要写自定义 loss，3—5 天，收益在部署阶段才体现 |
| 模型集成 | 推理翻倍，项目还没到拼最后 1 个点的时候 |
| 复杂合成数据管线 | 投入产出比低，A5 的简易版就够 |
| 自研采样器 | 先用“复制图片”验证有没有用，再决定要不要写代码 |
| 一上来读综述 | 综述解决“知道有哪些”，这张表已经给了，直接动手 |
