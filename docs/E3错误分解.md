# E3 错误分解：完整流程

> 日期：2026-11-01
> 目的：把“漏检 51 个裸头”拆成**能动手的几类**，每类给出特征画像和下一步动作。
> 脚本：[`scripts/error_analysis.py`](../scripts/error_analysis.py)
> 基线：`train4/best.pt`，SHWD val（282 张 / 151 个 head / 747 个 helmet），imgsz 640。

## 0. 为什么不能只看“漏了 51 个”

同样叫漏检，原因可能完全不同：

- 目标太小，模型根本没看见 → 调分辨率；
- 看见了但分数低 → 调阈值；
- 看见了但判成别的类 → 换分类策略；
- 框偏了 → 改回归/增强；
- 场景太暗太挤 → 补数据或换场景。

处理手段完全不一样。**错误分解就是把“漏检”这个总账拆成这五笔明细。**

## 1. 五类错误的定义

对每一个 GT 框，找和它 IoU 最大的预测框，然后按下面顺序判定：

| 类型 | 判别条件 | 含义 | 该做什么 |
|---|---|---|---|
| **A 判对** | IoU≥0.45 且类别对，conf≥工作点 | 正常 | — |
| **B 误合规** | IoU≥0.45 但判成 helmet，conf≥工作点 | 看见了，判错类 | 分类边界 / 复核分类器 |
| **C 低置信** | IoU≥0.45 类别对，但 conf<工作点 | 看见了，不敢报 | 调阈值（有代价，见 §5） |
| **D 定位偏差** | 0.1 ≤ IoU < 0.45 | 框偏了/被挤 | 增强、NMS 参数 |
| **E 完全没检出** | IoU < 0.1 | 模型没看见 | 分辨率、切片、补数据 |

> IoU 阈值 0.45、工作点 conf 0.25，与混淆矩阵口径一致。

## 2. 操作流程（一步一步来）

### 第 0 步：准备

- 权重：`ultralytics-8.3.163/ultralytics-8.3.163/runs/detect/train4/weights/best.pt`
- 数据：`cfg/datasets/SHWD.yaml`（val = SHWD 的 282 张）
- 确认 `labels/val` 和 `images/val` 一一对应（之前已验证 0 缺失）

### 第 1 步：跑脚本

```bash

  --weights "F:\Competition\ultralytics-8.3.163\ultralytics-8.3.163\runs\detect\train4\weights\best.pt" ^

```

产物：

```text
runs/error_analysis/
  summary_val.md    # 汇总表（先看这个）
  boxes_val.csv     # 每个 GT 框一行，含尺寸/亮度/拥挤度/最近 helmet 重叠
  crops/            # E 类的裁剪图，用来人眼看
```

### 第 2 步：看汇总表

先看 head 那一段的五类分布。如果 E 和 C 占大头 → 是“看的能力”问题；如果 B 占大头 → 是“判的能力”问题。

### 第 3 步：看画像

每一类的中位尺寸、亮度、同图目标数、贴边比例，决定用哪种手段：

| 画像 | 指向 |
|---|---|
| 小（<32×32） | 分辨率 / P2 / 切片 |
| 贴边比例高 | 裁剪策略、letterbox 方式 |
| 同图目标数高 | 密集场景，NMS/切片 |
| 与最近 helmet 的 IoU 高 | 标注边界问题（头盔框盖住了裸头） |

### 第 4 步：人眼看 E 类

`crops/` 里是按样本顺序存的，一次看 8—12 张，判断它们是不是同一类场景（夜间？远景？遮挡？）。

**这一步不能省**：数字告诉你“小”，但只有眼睛能告诉你“为什么小”“是不是真该检”。

### 第 5 步：按图像聚合，别被单张图带偏

打开 `boxes_val.csv`，按 `image` 列分组：如果 28 个漏检来自 3 张图，那结论不是“模型对小目标不行”，而是“模型在这几张图上崩了”——处理方式完全不同。

### 第 6 步：做阈值实验验证 C 类

C 类是“差一点就能救”的样本。别直接调阈值，先算清楚代价：

```python
# 从 boxes_val.csv 直接算
tp(c) = #{IoU≥0.45, 类别对, conf≥c} / 总数
wrong(c) = #{IoU≥0.45, 判成 helmet, conf≥c}
```

如果“召回 +5 个点”的代价是“误合规 +10 个”，那这个阈值就不能降。

## 4. 三个发现（这才是 E3 的产出）

**① 失败主要来自“小”和“黑”。**
判对的中位尺寸 47×59，漏检的只有 23×26——线性尺寸差一倍，面积差 4 倍。

**② 漏检高度集中，不是均匀分布。**
28 个没检出的 head 来自 **12 张图**，其中 3 张就占了 19 个（`000031` 一张 10 个、`part2_002302` 5 个、`000844` 4 个）。我看了 `000031`：**夜间、密集人群、强逆光手电**，GT 几乎全在阴影里。

→ 结论不是“模型不会检小头”，而是“**模型在一类场景上整体失效**”。处理方式从“调分辨率”变成“补夜间的数据 / 判断夜间在不在范围”。

**③ 误合规的 11 个反而“大而自信”。**
中位 72×69（比判对的还大），置信度中位 0.84。这不是“看不清”，是**语义判断错**：大裸头被稳定地认成戴帽。

→ 这类靠调阈值没用，只能靠**分类器复核**或**检查标注**（有可能这几张图的 GT 本身有问题）。

## 5. 阈值实验：C 类能不能靠降阈值救

从 CSV 直接算（head 类，IoU 0.45）：

| conf | 召回（判对） | 误合规（判成 helmet） |
|---:|---:|---:|
| 0.25（当前） | 89（58.9%） | 11 |
| 0.20 | 90（59.6%） | 12 |
| 0.15 | 92（60.9%） | 13 |
| 0.10 | 92（60.9%） | 16 |
| 0.05 | 97（64.2%） | **21** |

**读法**：降到 0.05，召回只多 8 个点，但误合规从 11 涨到 21——**几乎翻倍**。

原因在 C 类的构成：18 个里只有 8 个是“head 分数低”，另外 10 个是“**helmet 分数低**”（模型在裸头上报了个低分头盔框）。降阈值同时放大了这两种，后一种是纯粹的反向作用。

**结论：head 阈值不能单独降。** 要么配“head 优先”的判定规则，要么上复核分类器。

## 6. 分诊决策树

```text
head 漏检 62 个
├─ 28 个完全没检出（小 + 夜间/拥挤，集中在 12 张图）
│   ├─ 夜间/逆光是否在业务范围内？
│   │   ├─ 在 → 补夜间数据 + 亮度增强 + 提高分辨率
│   │   └─ 不在 → 从 val 里剔除这类图，重算基线（否则指标失真）
│   └─ 同时试 imgsz 960 / P2 / SAHI（针对小目标）
├─ 11 个误合规（大 + 高置信）
│   └─ 复核分类器（C4）；顺便查这 11 个的 GT 有没有标错
├─ 18 个低置信（8 个 head / 10 个 helmet）
│   └─ 不要单独降阈值；配“head 优先”规则或分类器
└─ 5 个定位偏差
    └─ 先放着，优先级最低
```

## 7. 常见坑

| 坑 | 表现 | 避免 |
|---|---|---|
| 只看单张图下结论 | 看到 8 张夜视图就以为全是夜景 | 按 image 聚合再下结论 |
| 用 AP 代替分类统计 | “漏了 51 个”不知道是哪类 | 一定跑这五类分解 |
| 拿 val 调完阈值就报结果 | 阈值过拟合 val | 阈值在 val 选，test 验 |
| 忽略标注错误 | 把 B 类当模型问题 | B 类抽 5 张人眼看 |
| 混用阈值口径 | 58.9% 和 68.2% 打架 | 报告里写清 conf / IoU |
